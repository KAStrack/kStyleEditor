Install

Download

Copy the files from docs/dist/ on GitHub, or build them yourself with npm run build. There is no build step to use them. 

<link rel="stylesheet" href="k-style-editor.min.css">
<script src="k-style-css.min.js"></script>
<script src="k-style-editor.min.js"></script>

Or the two-file bundle, k-style.min.js and k-style.min.css, which carries both scripts.

FileWhat it is
k-style-css.min.jsThe parser and sanitiser (KStyleCss). The editor needs it; it is also the JavaScript SDK.
k-style-editor.min.jsThe editor (KStyleEditor). Load it after k-style-css.
k-style-editor.min.cssThe editor's stylesheet.
k-style.min.js / .cssBoth scripts in one file, and the stylesheet under the same name.

npm

npm install @kastrack/style-editor
import '@kastrack/style-editor/editor.css';
import KStyleEditor from '@kastrack/style-editor/editor';   // the editor
import KStyleCss from '@kastrack/style-editor';             // the sanitiser, also in Node

Quick start

<form method="post">
  <textarea name="field_css" id="field-css">color: #333;</textarea>
  <button>Save</button>
</form>

<script>
  KStyleEditor.attach('#field-css', { preview: true });
</script>

The textarea is hidden and the editor appears after it. Every change is written straight back into the textarea (with native input and change events), so the form posts as it always did. An editor that has not been touched does not rewrite the textarea, so attaching never changes what is saved.

What gets saved

Plain CSS declarations, one per line, with no selector or braces:

color: #1d4ed8;
padding: 8px 12px;
border: 1px solid #94a3b8;

With selector: '#signup .email' the textarea holds a whole rule instead:

#signup .email {
  color: #1d4ed8;
  padding: 8px 12px;
}

Reading is forgiving: either form loads, comments are dropped, the final semicolon is optional, and !important is kept. Declarations no control understands (a content, a vendor prefix, a second background) are kept exactly where they were, shown in the Code tab, and saved unchanged, unless you ask for strict. A control writes its properties back in the place the first of them stood, so the cascade between them and anything else does not change.

The full grammar is in SPEC.md.

Controls

A control is one titled row. Any control can go in either group, in any order. The defaults are:

Basic

Advanced

The Advanced tab groups them into sections (Typography, Background, Border, Size, Layout, Flex & grid, Position, Effects, Interaction, and Spacing if you move padding or margin there) and adds a filter box.

Every built-in control

Generated from the library on this page, so it is always current.

IdTitleSectionProperties

When a value is something a control cannot take apart (a calc(), two shadows, a gradient with stops), the control shows it as a dashed text box instead. Nothing is rewritten until you change it.

Custom controls

A control is a title, a section, and a list of fields. Each field edits one CSS property using one of the built-in field types. Pass definitions in controls for one editor, or register them for every editor: 

KStyleEditor.registerControl({
  id: 'accent',
  label: 'Accent colour',
  section: 'typography',               // where it sits on the Advanced tab
  fields: [
    { type: 'color', prop: '--accent' }
  ]
});

KStyleEditor.attach('#css', { basic: ['accent', 'color', 'padding'] });

Every field also takes label (a small title above it, needed when a control has more than one field) and key (its name for labels, default the property).

A new field type

KStyleEditor.registerFieldType(name, factory) adds one. The factory gets (spec, ctx) and returns { el, props, refresh() }: props lists the properties it owns, ctx.get(prop) reads a value, and ctx.commit(props, declarations) replaces the owned properties. Look at FIELD_TYPES.text in the source for a short one.

Preview

Built-in box

KStyleEditor.attach('#css', { preview: true, previewContent: 'Sign up' });

A real element

KStyleEditor.attach('#css', { preview: '#field-12 input' });

The element's own style attribute is remembered. Each change puts it back and applies the saved declarations on top as inline styles, so removing something in the editor really removes it, and destroy() (or setPreview() to another element) leaves it as it was found. If your own code changes the element's inline style while an editor is attached, the editor will put back the version it remembered.

Events

editor.on('change', function (css, payload) {
  // payload: { css, declarations, source }
  // source: 'control', 'code' or 'api'
});

editor.on('tab', function (name) { … });

The textarea also gets native input and change events on every change, so existing form code (dirty-checking, autosave) works unchanged. An error thrown by a listener is reported to the console and does not stop the others.

Labels and translation

Every interface string is in KStyleEditor.DEFAULT_LABELS; override any of them. Control titles go in controls, keyed by control id, and field titles by id.key (the field's key, or its property). Section names go in sections: 

KStyleEditor.attach('#css', {
  labels: {
    basic: 'Simple', advanced: 'Everything', code: 'CSS',
    controls: {
      color: 'Text colour',
      'font.size': 'Text size'
    },
    sections: { flex: 'Flexbox and grid' }
  }
});

Security

The CSS arrives from a browser, so whatever a user can type into the Code tab (or post by hand) can reach your server. Sanitise it on the server, every time you render it. The editor's own sanitize option is a convenience, not a defence.

sanitize(), in every SDK, keeps a declaration only if all of these hold:

  • The property is a well-formed name (color, -webkit-x, --custom) and is on the allow-list. The default list is every property the built-in controls write plus common shorthands; pass your own, use 'border-*' for a prefix, or '*' for any.
  • It is not behavior or -moz-binding, which are refused whatever the list says.
  • The value has no { } < > \ or control characters, its quotes and parentheses balance, and it contains none of expression(, javascript:, vbscript:, @import, image-set(, image(, element(, cross-fade( or src(, ignoring case and spaces.
  • Every url() is relative, http(s):, or a data:image/png|gif|jpeg|webp URI. SVG data URIs are refused.

The result is re-serialised from what was parsed, never passed through, so it is safe inside a <style> element or a style="" attribute (HTML-escape it for the attribute, as you would any text). The selector you pass is yours, not the user's; one containing { } < ;, a backslash or a comment is refused with an error.

Safe is not the same as harmless. Allowed CSS can still hide an element, cover the page with position: fixed, or load an image from another server (which tells that server someone viewed the page). If that matters, narrow the allow-list: drop position, z-index and the background-image family, for example.

Server SDKs

Six implementations of the same four functions, held to one shared set of conformance cases:

FunctionDoes
parse(css)Declarations, in order, as { property, value, important }. Never fails; never validates.
stringify(declarations, options)Writes them out; selector and pretty as in the editor.
clean(css, options){ declarations, rejected }; each rejection has a reason: property, blocked, not-allowed, value or url.
sanitize(css, options)stringify(clean(css).declarations): untrusted CSS in, safe CSS out.

Options are allow, selector and pretty, spelled the way each language spells things.

JavaScript / Node

const KStyleCss = require('@kastrack/style-editor');   // or window.KStyleCss in a browser

const css = KStyleCss.sanitize(row.css, { selector: '#field-12' });
const { declarations, rejected } = KStyleCss.clean(row.css, { allow: ['color', 'border-*'] });

PHP

PHP 8.1+, no dependencies. composer require kastrack/style-editor, or require 'sdk/php/autoload.php'.

use Kastrack\StyleEditor\Css;

echo '<style>' . Css::sanitize($row['css'], ['selector' => '#field-12']) . '</style>';

$result = Css::clean($row['css'], ['allow' => ['color', 'border-*']]);
// $result['declarations'], $result['rejected']

Python

Python 3.8+, standard library only. The package is in sdk/python.

import kstyle_editor

css = kstyle_editor.sanitize(row.css, selector="#field-12")
result = kstyle_editor.clean(row.css, allow=["color", "border-*"])
# result["declarations"], result["rejected"]

C# / .NET

.NET 8+, no dependencies. The project is in sdk/dotnet.

using Kastrack.StyleEditor;

var css = KStyleCss.Sanitize(row.Css, new StyleOptions { Selector = "#field-12" });
var result = KStyleCss.Clean(row.Css, new StyleOptions { Allow = new[] { "color", "border-*" } });
// result.Declarations, result.Rejected

Go

Go 1.21+, standard library only.

import "github.com/KAStrack/kStyleEditor/sdk/go/kstyle"

css, err := kstyle.Sanitize(row.CSS, kstyle.Options{Selector: "#field-12"})

Browser support

The current versions of Chrome, Edge, Firefox and Safari. The scripts are ES5 and need nothing newer than classList, dataset and <details>; the stylesheet uses custom properties and, for narrow editors, container queries (without them the layout still wraps, a little less tidily).
